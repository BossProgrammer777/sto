# 🛞 Бот записи на шиномонтаж (помощник МОП)

Telegram-бот для операторов сети шиномонтажей. Оператор выбирает
**город → дату → свободное время**, вводит данные клиента, а бот сам
пишет запись в Google-таблицу и помечает слот занятым. Поле
«МОП Запись» бот заполняет автоматически по Telegram ID оператора.

## Возможности (этап 1)
- Доступ только для операторов из whitelist (по Telegram ID).
- Выбор поста: Киев Деревообробна, Киев О. Терьохіна 5/7, Софиевская Борщагивка, Харьков Шевченко, Харьков Майдан Захисників, Днепр, Львов.
- Киев Деревообробна — 2 поста, кнопка одна: пост бот выбирает сам по диаметру.
  R19 и больше (а также РОЗВАЛ/СТО/без диаметра) — сначала ПОСТ №1, R13–R18 —
  сначала ПОСТ №2; если на «своём» посту это время занято — берёт другой.
  Время показывается, если оно свободно хоть на одном посту. Пост виден в сводке.
  Граница — `SECOND_POST_MAX_DIAMETER` в config.py. На листах без ПОСТ №2
  (сентябрь и раньше) всё идёт на ПОСТ №1.
- Блок поста в таблице ищется по заголовку над ним (`City.labels` в config.py), а не по порядку колонок.
- Показ **только свободных** слотов на выбранный город+дату.
- Разный набор полей по городу (упрощённая / полная раскладка).
- Выпадающие значения (диаметр, тип авто, имена МОП) читаются из таблицы.
- «МОП Запись» — выбор из списка операторов (значения из таблицы).
- Поиск записи по номеру заказа/телефона (текущий + следующий месяц),
  удаление (освобождение слота) и перенос на другой слот/город.

## Архитектура записи (подход А — прямая запись в простыню)
Бот пишет данные записи **прямо в ячейки нужного слота** «красивой» простыни
(город/дата/время → точная ячейка блока). Свободные слоты определяются как:
**ячейка «Номер заказа» белая и пустая** (красный = занято/закрыто,
оранжевый = недоступно — не показываются).

## Задел на этап 2 (заложено в архитектуру, не реализовано)
- Автопрозвон/напоминание за N часов (колонка «ПРОЗВОН МОП ШМ»).
- Уведомление на конкретный пост при новой записи.
- Автостатистика по дням/городам (+ «Ориент. стоимость»).

## Переменные окружения
См. `.env.example`. Ключевые:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `SPREADSHEET_ID` | ID Google-таблицы |
| `GOOGLE_CREDENTIALS_JSON` | JSON-ключ сервисного аккаунта (целиком) |
| `ALLOWED_OPERATOR_IDS` | Telegram ID операторов через запятую (whitelist). Пусто = доступ открыт всем |
| `MONTHS_AHEAD` | на сколько месяцев вперёд показывать даты (1 = до конца следующего) |

## Запуск локально
```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить значения
python bot.py
```

## Калибровка таблицы
Перед боевым запуском один раз запусти калибровку — она печатает реальную
структуру листа (блоки городов, метки дат, выпадающие списки):
```bash
python inspect_sheet.py
python inspect_sheet.py --month "ШМ Сентябрь 26"
```
По выводу финализируется геометрия грида в `sheets.py`.

## Деплой на Railway
1. Репозиторий → New Project → Deploy from GitHub (ветка `main`).
2. Variables → задать переменные из таблицы выше.
3. Railway сам поднимет процесс `worker: python bot.py` (Procfile/railway.json).

## Структура проекта
```
bot.py            — точка входа, ConversationHandler (стейты, поток записи)
config.py         — города, раскладки, поля, выпадающие списки, env
calendar_utils.py — имена листов, метки дат, слоты времени
keyboards.py      — кнопки (ReplyKeyboardMarkup)
sheets.py         — слой Google Sheets (чтение слотов, запись, validation)
inspect_sheet.py  — калибровочный скрипт по реальной таблице
```

## Веб-прототип онлайн-записи (`web/`)
`web/index.html` — копия страницы «Шиномонтаж» rezina.cc с кнопкой «Онлайн-запис»
(адреса → календарь → диаметр/время → контакты). Один файл, открывается в браузере.

- **Живой режим:** если задан адрес API (`API_URL_DEFAULT` в файле или `index.html?api=https://…`),
  расписание читается из таблицы через бота (`web_api.py`, `GET /api/days?city=…`), обновление ~30 с.
  API отдаёт только время/цвет/занятость слота — без номеров заказов, телефонов и имён МОП.
- **Демо-режим** (адрес не задан): расписание генерируется по тем же правилам, что у бота.
- Правила как у бота: старт только на белом слоте, R20+ в Киеве = 2 слота, даты до конца
  следующего месяца; перед записью — свежая перепроверка слота.
- Запись с сайта пока **не пишется в таблицу** (хранится только в браузере).
- Фото городов: положите `web/img/{kyiv,sofiyivska,kharkiv,lviv,dnipro}.jpg` —
  они заменят нарисованный фон карточек.

### API на Railway
Бот поднимает API в том же процессе на порту `PORT` (Railway задаёт сам, по умолчанию 8080).
Чтобы сайт его видел: Railway → сервис → Settings → Networking → **Generate Domain**.
Выключить API: переменная `WEB_API=false`.

## Хранение шин → группа филиала
Для поста можно подключить таблицу хранения (колонки `ФИО | Ряд | Место | Шины | Комментарий`)
и группу филиала. Тогда после выбора МОП бот спрашивает «📦 Клиент с хранения?», ищет клиента
по ФИО, а после записи пишет в группу: клиент, ряд/место, шины, `шм+хр дата время`, пост, заказ, МОП.

Включается переменными (сейчас — для Киев Деревообробна, ключ `KYIV`):
`STORAGE_KYIV_SHEET` (ссылка или ID таблицы), `STORAGE_KYIV_TAB` (лист, необязательно),
`STORAGE_KYIV_CHAT` (ID группы — добавьте бота в группу и напишите там `/chatid`).
Другие филиалы — так же, с ключом поста: `STORAGE_LVIV_SHEET`, `STORAGE_LVIV_CHAT`…
