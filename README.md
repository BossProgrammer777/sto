# 🛞 Бот записи на шиномонтаж (помощник МОП)

Telegram-бот для операторов сети шиномонтажей. Оператор выбирает
**город → дату → свободное время**, вводит данные клиента, а бот сам
пишет запись в Google-таблицу и помечает слот занятым. Поле
«МОП Запись» бот заполняет автоматически по Telegram ID оператора.

## Возможности (этап 1)
- Доступ только для операторов из whitelist (по Telegram ID).
- Выбор города: Киев, Софиевская Борщагивка, Харьков, Днепр, Львов.
- Показ **только свободных** слотов на выбранный город+дату.
- Разный набор полей по городу (упрощённая / полная раскладка).
- Выпадающие значения (диаметр, тип авто, имена МОП) читаются из таблицы.
- Авто-заполнение «МОП Запись» по Telegram ID — честный учёт, кто записал.

## Архитектура записи (подход Б — по умолчанию)
Бот пишет запись в служебный «плоский» лист `Записи_Бот`
(город, дата, время, тел., заказ, диаметр, тип, стоимость, МОП, статус),
не трогая форматирование «красивой» простыни. Это безопасно и удобно для
статистики/прозвона. Свободные слоты определяются как:
**пустая ячейка «Номер заказа» в простыне** И **нет активной записи бота**
в плоском листе на этот слот.

Опционально можно включить прямую запись в простыню (подход А):
`WRITE_TO_GRID=true`.

## Задел на этап 2 (заложено в архитектуру, не реализовано)
- Автопрозвон/напоминание за N часов (колонка «ПРОЗВОН МОП ШМ»).
- Уведомление на конкретный пост при новой записи.
- Автостатистика по дням/городам (+ «Ориент. стоимость»).

Плоский лист `Записи_Бот` + `telegram_id`/`timestamp` дают готовую основу
для всего этого.

## Переменные окружения
См. `.env.example`. Ключевые:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `SPREADSHEET_ID` | ID Google-таблицы |
| `GOOGLE_CREDENTIALS_JSON` | JSON-ключ сервисного аккаунта (целиком) |
| `OPERATORS_JSON` | `{"<telegram_id>":"<Имя МОП>"}` — маппинг и whitelist |
| `FLAT_SHEET_NAME` | имя плоского листа (`Записи_Бот`) |
| `DAYS_AHEAD` | на сколько дней вперёд показывать даты |
| `WRITE_TO_GRID` | `true`, если писать прямо в простыню (подход А) |

## Запуск локально
```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить значения
python bot.py
```

## Калибровка таблицы
Перед боевым запуском один раз запусти калибровку — она печатает реальную
структуру листа (блоки городов, метки дат, выпадающие списки):
```bash
python inspect_sheet.py
python inspect_sheet.py --month "ШМ Сентябрь 26"
```
По выводу финализируется геометрия грида в `sheets.py`.

## Деплой на Railway
1. Репозиторий → New Project → Deploy from GitHub (ветка `main`).
2. Variables → задать переменные из таблицы выше.
3. Railway сам поднимет процесс `worker: python bot.py` (Procfile/railway.json).

## Структура проекта
```
bot.py            — точка входа, ConversationHandler (стейты, поток записи)
config.py         — города, раскладки, поля, выпадающие списки, env
calendar_utils.py — имена листов, метки дат, слоты времени
keyboards.py      — кнопки (ReplyKeyboardMarkup)
sheets.py         — слой Google Sheets (чтение слотов, запись, validation)
inspect_sheet.py  — калибровочный скрипт по реальной таблице
```
